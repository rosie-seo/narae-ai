# 로그인 QA 시나리오

Narae AI 프로토타입의 로그인·계정 관련 화면에 대한 테스트 시나리오입니다.

- **대상 화면** : 로그인(`login.html`), 회원가입 신청(`signup.html`), 비밀번호 재설정 안내(`password-reset.html`), 공통 헤더 사용자 메뉴
- **작성 기준** : 2026-09-28 기준 구현 내용
- **전제** : 서버 인증이 아직 없는 프로토타입으로, 계정·비밀번호·실패 횟수는 모두 브라우저 `localStorage`에 저장됩니다.

---

## 1. 테스트 준비

### 1.1 실행

프로젝트 루트에서 정적 서버를 띄운 뒤 로그인 화면으로 접속합니다.

```bash
python3 -m http.server 8777
# http://localhost:8777/resources/pages/login.html
```

### 1.2 테스트 계정 (비밀번호 공통 `1234`)

| 권한 | 아이디 | 계정 주인 | 소속 | 비고 |
| --- | --- | --- | --- | --- |
| 관리자 | `admin` | 이준혁 과장 | 기획조정실 · 정보화담당관 | 관리자 설정 버튼 노출 |
| 부서장 | `chief` | 김민준 과장 | 기획조정실 · 기획예산담당관 | |
| 과장 | `manager` | 강현우 과장 | 기획조정실 · 혁신행정담당관 | |
| 담당자 | `staff` | 류채원 담당자 | 기획조정실 · 혁신행정담당관 | **임시 비밀번호 상태** |

### 1.3 상태 초기화

케이스 간 상태가 섞이지 않도록, 각 그룹 시작 전 브라우저 콘솔에서 실행합니다.

```js
['krds_auth_v1','krds_login_fails_v1','krds_password_state_v1','krds_signup_requests_v1']
  .forEach(k => localStorage.removeItem(k));
Object.keys(localStorage)
  .filter(k => k.startsWith('krds_work_reports_v1'))
  .forEach(k => localStorage.removeItem(k));
location.reload();
```

### 1.4 저장소 키

| 키 | 내용 |
| --- | --- |
| `krds_auth_v1` | 로그인 상태 (아이디 · 사용자명 · 권한 · 로그인 시각) |
| `krds_login_fails_v1` | 아이디별 비밀번호 오류 횟수 |
| `krds_password_state_v1` | 임시 비밀번호 발급일 · 변경 이력 · 현재 비밀번호 |
| `krds_signup_requests_v1` | 회원가입 신청 내역 |
| `krds_work_reports_v1::{이름}` | 사용자별 업무보고 저장본 |

## 3. 알려진 제약 (테스트 제외 항목)

프로토타입 단계라 아래 항목은 **정상 동작이 아닌 미구현**입니다. 결함으로 등록하지 않습니다.

1. **임시 비밀번호 만료 미적용** — 사용 기한은 화면에 표시만 되고, 기한이 지나도 임시 비밀번호로 로그인됩니다.
2. **서버 인증 없음** — 계정·비밀번호·오류 횟수가 브라우저 `localStorage`에 평문으로 저장됩니다. 브라우저·시크릿 창이 다르면 상태가 공유되지 않습니다.
3. **계정 잠금은 브라우저 단위** — 다른 브라우저에서는 잠금이 적용되지 않습니다.
4. **회원가입 승인 화면 없음** — 신청은 저장만 되고 실제 계정이 만들어지지 않습니다. 임시 비밀번호 메일 발송도 없습니다.
5. **비밀번호 찾기 없음** — 잠금 해제는 모달의 `초기화 요청 보내기`로만 시뮬레이션됩니다.
6. **화면 접근 제어 없음** — 로그아웃 상태에서도 내부 화면 URL로 직접 접근할 수 있습니다(헤더만 로그인 버튼으로 바뀜). 리다이렉트가 적용된 화면은 `password-reset.html` 뿐입니다.
